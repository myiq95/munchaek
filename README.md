# 문장 — 나만의 서재

## GitHub Pages 배포
1. 압축을 풀고 `index.html`, `manifest.webmanifest`, `sw.js`를 저장소 최상위에 올립니다.
2. GitHub 저장소의 **Settings → Pages**에서 `Deploy from a branch`를 선택하고 `main` / `/ (root)`로 저장합니다.
3. 배포된 `https://사용자.github.io/저장소명/` 주소를 엽니다. HTTPS에서 서비스 워커가 동작합니다.
4. iPhone Safari: 공유 버튼 → **홈 화면에 추가**. Android/데스크톱: 브라우저 메뉴의 설치 기능을 사용합니다.

## 포함 기능
- 서재 목록 및 개별 삭제, 이어 읽기 위치 저장(브라우저 로컬 저장소)
- TXT / MD / HTML 읽기, DOCX 본문 추출, EPUB 본문 추출, PDF 브라우저 뷰어
- UTF-8 우선 디코딩 후 한글 CP949(EUC-KR) 대체 디코딩
- 한국어 장/화/부/절/편 및 프롤로그·에필로그 등의 목차 탐지, 없으면 임의 목차 생성
- 글꼴·글자 크기·자간·줄 간격·낮/밤 테마
- Web Speech API 기반 시스템 음성 읽기
- PWA 앱 셸 캐시

## 중요한 한계
- 서재 데이터는 해당 브라우저/기기의 로컬 저장소에 저장됩니다. 브라우저 데이터 삭제 시 사라질 수 있으므로 원본 파일을 별도 보관하세요. 다른 기기와 자동 동기화되지 않습니다.
- PDF는 브라우저 내장 PDF 뷰어로 표시합니다. PDF 본문에서 앱 목차를 자동 생성하지는 않습니다.
- DOCX/EPUB 압축 해제는 브라우저의 `DecompressionStream('deflate-raw')` 지원이 필요합니다. 지원하지 않는 브라우저에서는 해당 파일을 열지 못할 수 있습니다.
- 시스템 TTS의 음성·속도 지원은 운영체제와 브라우저 설정에 따라 달라집니다.
- 앱 셸은 오프라인 캐시되지만, 아직 열지 않은 파일은 자동 보관되지 않습니다. 로컬에서 파일을 다시 열거나 온라인 상태에서 앱을 방문해 셸을 캐시해야 합니다.
- PDF 파일 객체 URL은 현재 실행 세션에서만 유효합니다. 새로고침/재실행 뒤 PDF를 다시 열어야 할 수 있습니다.
